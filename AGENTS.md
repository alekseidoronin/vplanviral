# AGENTS.md

ViralDzen — библиотека: вирусные материалы Дзена по теме, которую назвал человек. Без браузера, без логина в Яндекс.

Отвечай по-русски. Плейбук смены — `skills/viraldzen-collect/SKILL.md` (копии: `.cursor/skills/viraldzen-collect/`, `.agents/skills/viraldzen-collect/`). README — людям, сюда не копируй.

В репозитории нет чужих сайтов, каналов и списков тем «под автора». Тема всегда от текущего пользователя.

## Старт

Пока человек не назвал тему и не прислал ссылку Дзена — не запускай `collect`. Поприветствуй: слова, канал, статья или хаб `dzen.ru/topic/…`. В конце смены человек должен получить HTML-таблицу.

## Куда писать

- Статус после работы — `handoff.md` (в git не коммитить)
- Сырые выгрузки — только в `data/`

## Витрина канала «В-план»

Виральщик сам кладёт найденную тему во вкладку **«План +»**. Это постоянное имя: не переименовывай её в «Ленту» и не меняй название ни в коде, ни в данных.

Куда: отдельная карточка в `data/inbox.json` проекта `~/Vplanist` на сервере витрины. Одна тема, одна новая карточка. Поля:

- `title` — заголовок
- `hook` — хук
- `source_url` — ссылка на источник
- `source_date` — дата источника
- `date` — момент добавления во вкладку, по Москве: `ДД.ММ.ГГГГ ЧЧ:ММ МСК`. Это не дата источника. Команда проставляет его сама.
- `why` — почему зайдёт

Номера очереди и номера статей не ставь и не меняй. Их пишет диспетчер.

Чужие карточки, `published.json` и HTML-файлы витрины не трогай. Не перезаписывай файл целиком и не подменяй его своей копией: к уже лежащему JSON добавь только свою карточку, остальные байты оставь как были. Карточки, которые уже лежат в «План +», не правь и не удаляй. Не считай их очередью выпуска, но сверяй с ними дубли.

Перед записью проверь дубли по заголовку и по ссылке источника: и в `data/inbox.json`, и в `published.json`. Совпадение есть — новую карточку не пиши.

Порядок одной командой:

```bash
python3 -m viraldzen plan-plus --card data/plan-plus-YYYY-MM-DD.json
```

Команда читает очередь и опубликованные темы, при дубле останавливается, перед правкой копирует `data/inbox.json` в бэкап, дописывает карточку и коммитит в репозитории витрины только `data/inbox.json`. Push не делай. `--dry-run` только проверяет дубли.

Доступ к витрине только из переменных окружения. В коде, чате, git, PR и `handoff.md` не пиши адрес сервера, ключ и токен. Если переменной нет, остановись и назови её имя. Не проси прислать секрет в чат.

- `VITRINE_HOST` — хост SSH
- `VITRINE_USER` — пользователь SSH
- `VITRINE_SSH_KEY` — секрет: PEM-ключ или путь к файлу ключа
- `VITRINE_PATH` — необязательно. Если не задан, проект `~/Vplanist`
- `VITRINE_PUBLIC_URL` — необязательно. Если задан, после записи открой его и проверь, что карточка видна во вкладке «План +»

В `handoff.md` зафиксируй заголовок, число карточек в списке и что коммит на витрине прошёл. `inbox.json` витрины в этот публичный репозиторий не коммить. Доступа нет — локальную карточку в `data/` сохрани и не пиши, что выкладка удалась.

## Запреты

- Не подставлять чужие темы, сайты и каналы из прошлых чатов
- Не копипастить статью Дзена как готовый материал человека
- Не коммитить `data/`, ключи, cookies, заполненный `handoff.md`
- Не открывать браузер, если хватает `python3 -m viraldzen`
- Не ждать `input()`: у агента нет TTY. Флаги `--topic` / `--slug` / `--pick` / `--channel` / `--url` / `--channel-only`

## Как проверить, что смена закрыта

1. Человека поприветствовали и спросили тему **или** канал, если он сам это не принёс
2. В `handoff.md` есть статус, команда, выбранная тема (название + slug + подписчики, если хаб нашёлся) или канал/статья, **путь к HTML**, CSV/SQLite, число строк
3. Если меняли код — `python3 -m unittest discover -s tests -v` зелёный
4. В git-диффе нет `data/` и cookies
5. Если тема для «В-план» и заданы `VITRINE_HOST`, `VITRINE_USER`, `VITRINE_SSH_KEY` — карточка добавлена через `plan-plus`, в `handoff.md` есть число карточек. Переменных нет — в `handoff.md` блокер, без выдуманной выкладки

## Команды

```bash
python3 -m viraldzen topics --query "<тема>"
python3 -m viraldzen channel --url "https://dzen.ru/<канал>"
python3 -m viraldzen collect --topic "<тема>" --pick 1 --pages 2 --top 20 --out-dir data
python3 -m viraldzen collect --channel "https://dzen.ru/<канал>" --channel-limit 3 --out-dir data
python3 -m viraldzen collect --channel "https://dzen.ru/<канал>" --channel-only --out-dir data
python3 -m viraldzen collect --url "https://dzen.ru/a/<id>" --out-dir data
python3 -m viraldzen html --db data/viral.sqlite --out data/viral.html
python3 -m viraldzen plan-plus --card data/plan-plus-YYYY-MM-DD.json
python3 -m unittest discover -s tests -v
```
